## Learnings

**User decisions** (final; do not re-ask):
- Activity **replaces** Tour and is generic (a free-text `type`). Tour is deleted from pms-ts with **no data migration**. `viorder` (the guest React app, `C:\apps\ps\viorder`) is **not touched**; its tour pages keep calling the old, unconfigured service.
- The backend goes in **vom-assistant** (`C:\apps\ps\vom-assistant`, Spring Boot 3 / Java 17 / embedded Infinispan). The scope is backend plus pms-ts admin. The guest API is backend only, under `/{tenant}/reception/activity/**`.
- **Two stores:**
  - `Activity`, with the pricing tiers embedded in it.
  - `ActivitySession`, with its requests embedded and a `version` field.
  - This keeps the capacity check atomic under the compare-and-swap update (`cache.replace(k, old, new)`).
  - Sessions are **lazy**: they are computed from the activity config and persisted only on the first successful action.
- A session is confirmed when **approved headcount ≥ minGuests, OR the host confirms it**. Everyone counts equally (no adult/kid split).
- **Out of scope:** invoice sync, email/SMS/push notifications, WebSocket/SSE realtime, and the viorder UI.
- **Git workflow:** always create a branch before any change: `feature/<snake_case>` off `develop`, in every repo touched. The user asked for this explicitly, and it is saved in memory as `branch-before-changes`.

**Traps the reviews caught** (already fixed in the plan; do not reintroduce):
- **Enum name clash:** protostream enum value names are package-scoped. `CONFIRMED`, `REJECTED` and `CANCELLED` already exist (OrderStatus). Use prefixed names, like `config/protoadapter/SInvoiceStatusAdapter.java:10-14`.
- **Keycloak scope names:** authorities are built as `rsname` and `rsname:scope` (`vom-assistant/.../config/SecurityConfiguration.java:111-121`). The Keycloak scopes must be plain `write`, `create` and `delete` on resource `activity`, not `activity:write`.
- **Production config:** production mounts a **separate** `devops/docker-swarm/config/assistant/infinispan.xml` (rocksdb **14.0** namespace). A missing cache there stops the backend from starting. The devops repo is **not on this machine**.
- **Netlify:** production pms-ts is built by **Netlify** (sites `pmsdr-ps` and `pmsts-ps`), not by the Dockerfile. `REACT_APP_ACTIVITY_ENDPOINT` must be set on both sites.
- **Baseline test failures:** vom-assistant `develop` already fails 5 test classes: `TaxControllerTest`, `TaxPolicyControllerTest`, `TaxPolicyEvaluatorTest`, `TaxPolicyServiceTest` and `TaxPreviewServiceTest`. The gates are "no failures beyond the baseline". `study/telegrambot/TelegramBotApplicationTests` (`@SpringBootTest`, about 5 minutes) is the only test that proves the caches, schema and profile boot.
- **Existing CAS pattern:** Booking's CAS (`service/impl/BookingServiceImpl.java` ~172-263, 298-337, 348-374) returns null, which becomes a 404, on any failure. The plan uses a scoped `@RestControllerAdvice` with **409** instead. The `bookings` cache has a 5-minute lifespan and must not be copied for the activity caches.
- **Slot loop:** the slot generator must loop over int minutes. `LocalTime.plusMinutes` wraps at midnight and can loop forever.
- **User list authority:** `listUsers` (GET `/*/user/**`) needs the `user` authority. The host picker must fall back to free text and never call `handleUnauthorized`.
- **pms-ts error handling:** axios throws on 4xx, so `res.status === 401` checks never fire. Handle errors in `catch` with `axios.isAxiosError` (`src/App.tsx:291`).

**Other facts established:**
- The old Tour admin UI was a non-functional stub: `REACT_APP_TOUR_*` is in no `.env`, and the backend was never found. An unmerged `origin/feature/tour_management` branch exists in vom-assistant; the plan ignores it.
- vom-assistant has an **unrelated uncommitted change**, `.run/AssistantApplication_LOCAL.run.xml`. Never stage it: commit with explicit paths, never `git add -A`.
- There is no mvnw; use `mvn` 3.9.16. pms-ts has no tests. Its gates are `npx tsc --noEmit -p .` (passes today) and `npm run build` (passes, with warnings).
